# 仕様書 — ギター指板トレーニング

このファイルが**唯一の正**です。実装を変更したら必ずここを更新し、
`tests/` のテストが仕様の各項目を検証している状態を保ちます。

各項目の `[S-xxx]` は仕様IDです。テストコードのタイトルにこのIDを含めてください。

---

## 1. アプリ全体

### 1.1 画面構成 [S-APP-01]

| 領域 | 内容 |
| --- | --- |
| モードタブ | 🎵 音名クイズ / 🎯 度数クイズ / 🎹 コードシェイプ |
| 設定パネル | 現在のモードに関係する設定のみ表示する |
| 問題表示 | 見出し（`#question-label`）・問題（`#question-note`）・補足（`#question-sub`） |
| 指板 | SVG。0（開放弦）〜24フレット、**1弦が上・6弦が下**、**0フレットが左** |
| フィードバック | 正解／不正解のメッセージ |
| 操作 | 「選択をクリア」（コードモードのみ）／「次の問題 →」／「スコアをリセット」 |
| スコア | 正解数・出題数・正答率・連続正解・最高連続 |

### 1.2 モード切替 [S-APP-02]

- モードは `note` / `degree` / `chord` の3種。
- `#app` に `is-note` / `is-degree` / `is-chord` のいずれか1つが付く。
- 設定パネルの `.mode-note` / `.mode-degree` / `.mode-chord` は、対応するモードのときだけ表示する。
- モードを切り替えてもスコアは**モードごとに独立**して保持される。

### 1.3 設定の永続化 [S-APP-03]

- 設定は localStorage キー `guitar-game-settings` に保存する。
- 読み込み時は既定値とマージするため、キーが増えても既存ユーザーの設定は壊れない。
- 保存値が現在の選択肢に存在しない場合（旧バージョンの値など）は既定値に戻して保存し直す。

### 1.4 共通設定 [S-APP-04]

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| チューニング | スタンダード / ドロップD / 半音下げ | スタンダード |
| サウンド | ON / OFF | ON |
| 音色 | アコースティック / ガット / クリーン / クランチ / ディストーション / ブリッジミュート | アコースティック |
| 音量 | 0〜100% | 23% |
| 自動送り | ON / OFF | **ON** |
| 練習モード（全ポジション表示） | ON / OFF | OFF |

### 1.5 自動送り [S-APP-05]

- **既定は ON。**
- ON のとき、**正解した場合のみ**一定時間後に自動で次の問題へ進む。
  - 音名クイズ・度数クイズ: 900ms
  - コードシェイプクイズ: 1300ms（アルペジオ再生を聴ける時間を確保）
- **不正解のときは自動で進まない**（正解を確認させるため）。
- OFF のとき、および不正解のときは「次の問題 →」ボタンにフォーカスが移る。
- モード切替・設定変更時は予約済みの自動送りタイマーを破棄する。

### 1.6 サウンド [S-APP-06]

- 指板をクリックすると、その位置の実音高が鳴る（回答済みでも鳴る）。
- 音名／度数クイズで不正解のときは、550ms 後に正解位置の音を鳴らす。
- コードシェイプクイズで正解したときは、シェイプを低音弦からアルペジオ再生する。
  不正解のときは 500ms 後に正しいシェイプをアルペジオ再生する。
- 音色を変更したときは 3弦開放を試聴再生する。

### 1.7 キーボード [S-APP-07]

- `Enter` または `Space` で「次の問題 →」（ボタンが有効なときのみ）。

## 2. 音名クイズ [S-NOTE]

### 2.1 出題 [S-NOTE-01]

- ランダムな音名を1つ出題し、その音がある指板上の位置をクリックして答える。
- 同じ音名が2問続けて出題されない。

### 2.2 設定 [S-NOTE-02]

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| 音名表記 | `C D E F G A B` / `ド レ ミ ファ ソ ラ シ` | 英語 |
| 出題範囲 | ナチュラル音のみ（7音） / 全12音 | ナチュラル |
| ♯/♭の表記 | シャープ / フラット / 両方 | シャープ |

### 2.3 判定 [S-NOTE-03]

- クリックした位置のピッチクラスが出題と一致すれば正解（オクターブ違いは問わない）。
- 正解: 押した位置に緑のマーカー、「正解！ 🎉」。
- 不正解: 押した位置に赤のマーカー、正解位置すべてに緑のマーカー、
  「残念… そこは 〇 です。〇 は緑の位置。」。

## 3. 度数クイズ [S-DEG]

### 3.1 出題 [S-DEG-01]

- 指板上にルートを青い **R** で表示し、そこから見た度数（例: `III`、`m3`）を出題する。
- ユーザーは該当する度数の位置をクリックして答える。
- 同じ度数が2問続けて出題されない。

### 3.2 設定 [S-DEG-02]

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| 度数の表記 | ローマ数字（♭III） / 音程名（m3） | ローマ数字 |
| 出題する度数 | コードトーン / メジャースケール / ナチュラル・ハーモニック・メロディックマイナー / メジャー・マイナーペンタトニック / ブルース / 全12音程 | コードトーン |
| ルートの決め方 | 毎問ランダム / ルート音を固定 / ルート位置を固定 | ランダム |
| ルートの弦 | 1〜6弦から複数選択（最低1本） | 6弦・5弦 |
| 回答できる範囲 | ルート周辺（±4フレット） / 指板全体 | ルート周辺 |

- ルートは 0〜12フレットに配置する。

### 3.3 判定 [S-DEG-03]

- 押した位置のルートからの度数が出題と一致し、かつ回答範囲内なら正解。
- 度数は合っているが回答範囲外のときは、通常の不正解とは区別したメッセージを出す。
- 不正解時は正解位置に緑のマーカーと度数ラベルを表示する。

## 4. コードシェイプクイズ [S-CHORD]

### 4.1 出題 [S-CHORD-01]

- コードネーム（例: `Cmaj7`）を出題し、指板を**複数クリック**して押さえる。
- 同じ「コード種類 × ルート位置」が2問続けて出題されない。

### 4.2 ボイシング [S-CHORD-02]

| ID | 表示 | 押さえる音 | 音数 |
| --- | --- | --- | --- |
| `triad` | トライアド（R・3rd・5th） | R, 3rd, 5th | 3 |
| `seventh` | セブンス（R・3rd・5th・7th） | R, 3rd, 5th, 7th | 4 |
| `guide` | ガイドトーン（R・3rd・7th／5th省略） | R, 3rd, 7th | 3 |

- 表の「音数」は**最低音数**であり、実際に鳴らす弦は**その本数から6本まで**可変。
  余った弦には構成音のいずれかを**オクターブ違いで重ねてよい**（バレーコードや開放コードの形）。
- 正解シェイプは理屈で網羅的に生成するのではなく、**定番コードフォームのカタログ
  （[S-CATALOG]）から導く**。実際に使われている押さえ方だけを正解とする。
- どの弦を使うか（隣り合う弦か、弦を飛ばすか）はカタログのタブ譜が決める。
  鳴らさない弦はミュートするものとして扱う。
- ボイシングはカタログエントリから次のように判定する。
  - `triad` … トライアド系のコード
  - `seventh` … セブンス系で省略音のないフォーム
  - `guide` … セブンス系で5度を省略したフォーム（シェルボイシング）

### 4.3 コードの種類 [S-CHORD-03]

- 出題できるのは**カタログに定番フォームがあるコードだけ**（`catalogQualities(voicing)`）。
- `triad`: メジャー / マイナー / ディミニッシュ / オーギュメント / サスフォー
- `seventh`: maj7 / 7th / m7 / m7♭5 / dim7 / mMaj7
- `guide`: maj7 / 7th / m7 / mMaj7
  - m7♭5 と dim7 は**♭5がコードの identity**なので5度を省略できず、シェルボイシングが存在しない。
- 複数選択でき、**最低1つは選択されている**状態を保つ。

### 4.4 ルート弦 [S-CHORD-04]

- 6弦 / 5弦 / 4弦 / 3弦 / 2弦 / 1弦から複数選択（既定は6弦・5弦、最低1本）。
- 選べるのは、そのボイシング・そのチューニングで**カタログに定番フォームがあるルート弦だけ**
  （`catalogRootStrings(voicing, tuning)`）。展開形を認めるため、高音弦もルートになりうる。
- スタンダード／半音下げ
  - `triad` / `seventh`: 6〜1弦すべて
  - `guide`: **6弦・5弦のみ**（シェルボイシングは低音弦にルートを置く形だけが定番）
- ドロップD
  - 6弦だけ音程が違うため、6弦を使う定番フォームはそのままでは和音として成立しない。
    よって**6弦ルートは選べない**（`triad` / `seventh` は5〜1弦、`guide` は5弦のみ）。
- チューニングを変えたとき、選べなくなったルート弦は自動的に選択から外れる。

### 4.5 カタログからの正解シェイプ導出 [S-CHORD-05]

- ルート位置は 0〜12フレットからランダムに選ぶ（そのフレット範囲でシェイプを作れない場合は
  17フレットまで探索する）。
- 正解シェイプは `catalogChordShapes(tuning, voicing, quality, root)` が返す。手順は次のとおり。
  1. カタログから、**コード種類が一致し、ボイシングが一致する**エントリを集める。
  2. そのチューニングで和音として成立するエントリだけ残す（`isShapeValidIn`）。
     カタログのタブ譜はスタンダードチューニング前提の記譜なので、
     弦の音程差が違うチューニング（ドロップD）では成立しないフォームがある。
  3. 出題されたルート位置に合わせて**フレット方向に平行移動**する。
     - 移動可能フォーム（開放弦を含まない）だけが移調できる。
       開放弦を含むフォームは、記譜どおりの位置でルートが一致するときだけ使う。
     - 移調後のフレットが 1〜24 に収まらないものは除外する。
  4. 同じ押さえ方が複数のファミリーに登場することがあるので、**位置集合で重複を除く**。
- 候補は次の優先順で並べ、先頭を画面表示用の代表シェイプとする。
  1. ルートが低い順（基本形が先、展開形が後）
  2. フォームの系統順（オープン → CAGED → ドロップ2 → ドロップ3 → シェル → トライアド）
  3. 音数が多い順（定番のバレーコード形を優先）
  4. 弦の広がりが狭い順

### 4.6 回答 [S-CHORD-06]

- 「ルートを表示する」ON（既定）のとき、ルート位置に青い **R** を表示し、
  ユーザーは**残りの構成音だけ**をクリックする。
- OFF のときはルートも含めて全構成音をクリックする。
- クリックした位置はオレンジの「選択中」マーカーになる。
  もう一度クリックすると選択を解除できる。
- 音数は可変（[S-CHORD-05]）なので、選択が**正解シェイプのいずれかと一致した時点で自動的に判定**する。
- 一致しないまま選び終えたときのために「**回答する**」ボタンを用意する。
  最低音数に達するまでは無効、判定後も無効。
- 選択できるのは最大で「6 − ルート表示分」音まで。
- 「選択をクリア」ボタンで、判定前の選択をすべて解除できる。
- 補足行には常に
  「ボイシング名 ／ ルート弦（何問目/全問） ／ ルート位置（表示ONまたは回答後のみ） ／ 選択状況」
  を表示する。選択状況は最低音数に届いていなければ「あと N 音以上（n 音選択中）」、
  届いていれば「n 音選択中（オクターブを足してもOK）」。

### 4.7 判定 [S-CHORD-07]

- 選んだ位置の集合が**正解シェイプのいずれかと完全一致**したときに正解とする
  （展開形でも、弦を飛ばした形でも正解）。
- 正解: 選んだ位置を緑のマーカーにし、各音に度数ラベル（`R` `3` `5` `M7` など）を表示。
- 不正解: 間違えた位置を赤で表示し、**選択と最も重なりの多い正解シェイプ**を緑で表示する。

### 4.8 複数ルート弦の連続出題 [S-CHORD-08]

- 1つのコードに対して、**選択したルート弦の数だけ小問（ステップ）**を出題する。
  例: 6弦・5弦を選んでいれば `Cmaj7` を6弦ルート → 5弦ルートの順で2回答える。
- ステップは**低音弦から高音弦の順**に並ぶ。
- **途中で間違えても中断せず、すべてのステップを回答させる**。
- スコア（出題数・正解数）は**小問ごと**に加算する。
- 「次へ」ボタンのラベルは、残りステップがあるとき `次のシェイプ →`、
  最後のステップでは `次の問題 →` になる。
- 自動送りが ON のときは、**正解したときのみ**次のステップ／次の問題へ自動で進む（1300ms後）。
  不正解のときはボタン操作で進む。
- 出題時、選択したすべてのルート弦でシェイプを作れるコードを優先して選ぶ。

### 4.9 押弦できるシェイプかの判定 [S-CHORD-09]

正解シェイプはカタログ（実際に使われている押さえ方）が正なので、この判定は
**カタログの品質チェックと指の本数表示**のために使う。次の2つを別々に扱う。

- **押弦幅**（押さえるフレットの最大値 − 最小値）
  - 最小フレットが 5未満（ローポジション）: **3フレット差以内**
  - 最小フレットが 5以上: **4フレット差以内**
  （`isSpanReachable`）
- **必要な指の本数**（`fingerCount`、親指は数えない）。本数は次のように数える。
  - 開放弦（0フレット）は指を使わない（0本）。
  - **最小フレット**に複数の音があるときは、人差し指のセーハで **1本**と数える。
    ただしセーハする弦の範囲の内側に、それより低いフレット（開放弦を含む）の音があるときはセーハできず、
    音の数だけ指が必要になる。
  - 最小フレット以外は、同じフレットでも 1音につき 1本と数える。
- `isPlayableShape` は「押弦幅が届く」かつ「指が4本以内（`MAX_FINGERS`）」のときに true を返す。
- カタログのフォームは原則としてこの条件を満たす。押弦幅の上限が保守的なため
  例外的に false になるエントリは、テストで既知の例外として固定してある。

## 5. 定番コードフォームのカタログ [S-CATALOG]

`src/core/chordCatalog.ts` は、教則本やレッスンサイトで実際に教えられている
「定番の押さえ方」を集めたカタログである。
**コードシェイプクイズの正解判定はこのカタログが唯一の根拠**である（[S-CHORD-05]）。
理屈の上で成立する形をすべて列挙するのではなく、**実在する押さえ方だけ**を正解とする。

### 5.1 データ形式 [S-CATALOG-01]

1エントリ（`CatalogShape`）が1つの押さえ方を表す。

| フィールド | 内容 |
| --- | --- |
| `id` | 一意な識別子 |
| `qualityId` | `CHORD_QUALITIES` のコード種別 id |
| `root` | このタブ譜が表すコードのルート音（ピッチクラス） |
| `name` | 押さえ方の通称 |
| `family` | 系統（下記） |
| `tab` | `x-3-2-0-1-0` 形式。**6弦→1弦**の順、`x` はミュート |
| `sourceId` | `CATALOG_SOURCES` の出典 id |
| `omits` | 意図的に省略している構成音（ルートからの半音距離） |
| `note` | 補足 |

系統（`ShapeFamily`）は次の6種類で、すべて1件以上のエントリを持つ。

| 系統 | 内容 | 件数 |
| --- | --- | --- |
| `open` | 開放弦を含むローポジションの定番形 | 40 |
| `caged` | CAGED システムの移動可能フォーム（バレーを含む） | 28 |
| `drop2` | ジャズのドロップ2（隣り合う4弦） | 72 |
| `drop3` | ジャズのドロップ3（1本飛ばした4弦） | 48 |
| `shell` | 5度を省いたシェル／ガイドトーン | 16 |
| `triad` | 3声のトライアドボイシング | 60 |

**転記ミスを防ぐため、データとして持つのはタブ譜だけ**とする。
ルート弦・転回形・度数・移動可能かどうかは持たせず、すべて導出関数で計算する（[S-CATALOG-03]）。

出典は `CATALOG_SOURCES` に URL 付きで記録する。

### 5.2 構成音の正しさ [S-CATALOG-02]

すべてのエントリは、次を満たすことをテストで機械的に検証する。

- 鳴っている音のピッチクラス集合が、`CHORD_QUALITIES` の `intervals` と**過不足なく一致**する。
- ただし `omits` に宣言した音は欠けていてよい。宣言していない音の欠落・余分な音は不正とする。
- `omits` に宣言した音が実際に鳴っている場合も不正とする。
- **省略できるのは5度だけ**。ルート・3度・7度は省略しない。
- 宣言した `root` のピッチクラスが実際に鳴っている。

### 5.3 導出する情報 [S-CATALOG-03]

`analyzeCatalogShape(shape)` が次を計算する。
カタログのタブ譜は**スタンダードチューニング前提の記譜**なので、解析は常に
スタンダード（`CATALOG_TUNING`）で行い、チューニングを引数に取らない。

- `positions` — 低音弦から高音弦の順の `Position[]`
- `intervals` — `positions` と同じ並びの、ルートからの半音距離（0〜11）
- `rootString` — ルート音が鳴っている弦のうち、**最も低音側**のもの
- `inversion` — **最低音の度数**を基準にした転回番号（0 = 基本形）
- `movable` — 開放弦を含まず、任意のフレットへ移動できるか
- `noteCount` / `minFret` / `maxFret`

規約:

- 名前に「N弦ルート」と書かれているエントリは、`rootString` が N と一致する。
- 転回形の呼び方は**最低音基準**で統一する。
  出典によっては「元のクローズドボイシングの転回番号」で呼ぶことがあるが、それは採用しない。
  そのため `drop2` / `drop3` / `triad` の名前には転回番号を書かず、`型1`〜`型4` と呼ぶ。
- `open` 以外の系統はすべて `movable` である。


### 5.4 押弦できる形であること [S-CATALOG-04]

- 押弦するフレットの幅（最大 − 最小）が**4フレット差以内**に収まる。
- [S-CHORD-09] の `isPlayableShape()` は押弦幅の制限が保守的なため、
  実在するにもかかわらず通らないエントリが存在しうる。
  そのようなエントリは**既知のリストとしてテストに固定**し、意図しない増減を検出する。

### 5.5 タブ譜の変換・移動 [S-CATALOG-05]

- `parseTab(tab)` — 6弦→1弦のフレット配列に変換する。`x` は `null`。
  6弦ぶんでない、または負数・数値でない要素があれば例外を投げる。
- `tabToPositions(tab)` — 低音弦から高音弦の順の `Position[]` に変換する。
- `transposeTab(tab, semitones)` — 半音単位で移動する。
  開放弦を含むシェイプ、または移動先が負のフレットになる場合は例外を投げる。

### 5.6 カタログの検索 [S-CATALOG-06]

`findCatalogShapes({ qualityId, family, movable })` で絞り込む。
`CHORD_QUALITIES` の11種すべてに1件以上のエントリが存在する。

### 5.7 生成ドキュメント [S-CATALOG-07]

`docs/CHORD_CATALOG.md` は `npm run catalog` でカタログから自動生成する。手で編集しない。
コード・押さえ方の通称・タブ譜・ルート弦・転回形・構成音・備考を系統ごとの表にまとめ、
末尾に出典の URL を並べる。

生成物が古くなっていないことをテストで検証する。
カタログを変更したら `npm run catalog` を実行してから `npm run check` を通すこと。


### 5.8 別チューニングでの成立可否 [S-CATALOG-08]

タブ譜はスタンダード前提なので、弦の音程差が違うチューニングでは和音として成立しない
フォームがある。`isShapeValidIn(entry, tuning)`（`src/core/catalogShapes.ts`）が判定する。

- 平行移動しても弦ごとの音程差は変わらないので、**判定はタブ譜そのものの位置で1回行えばよい**。
- スタンダード・半音下げ（全弦が均等に −1半音）ではすべてのフォームが成立する。
- ドロップD（6弦だけ −2半音）では、**6弦を鳴らすフォームがすべて成立しない**。

## 6. テスト方針

- `npm run check`（= `tsc --noEmit` + `vitest run`）が通ることをもって「仕様を満たしている」とする。
- テストは `tests/` に置き、`describe` / `it` のタイトルに仕様ID（例: `[S-CHORD-05]`）を含める。
  - `tests/core.test.ts` — 音名・度数・チューニング・コードシェイプ生成の純ロジック
  - `tests/catalog.test.ts` — 定番コードフォームのカタログの機械検証（構成音・ルート弦・転回形）
  - `tests/quiz.test.ts` — `Quiz` / `DegreeQuiz` / `ChordQuiz` の出題・判定ロジック
  - `tests/app.test.ts` — jsdom 上で `src/main.ts` を実際に起動する結合テスト
    （画面構成・モード切替・設定の永続化・**自動送り**・キーボード操作）
  - `tests/setup.ts` — Node 26 では `globalThis.localStorage` が undefined になり jsdom のものを
    覆い隠すため、メモリ実装を差し込む
- ロジック（`src/core`, `src/ui/*Quiz.ts`）は単体テストで網羅する。
- 新しい仕様を追加したら、対応するテストも必ず追加する。テストの無い仕様は未実装とみなす。
- 既存のテストを「通らないから」という理由で削除・スキップしない。仕様変更なら本書とテストを両方直す。
- ブラウザでの手動確認を行う場合、**localStorage の設定を書き換えたら必ず元に戻す**こと
  （検証のつもりでユーザーの設定を変えてしまう事故を防ぐ）。
  手動確認より `tests/app.test.ts` への自動テスト追加を優先する。
