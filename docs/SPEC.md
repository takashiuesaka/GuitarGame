# 仕様書 — ギター指板トレーニング

このファイルが**唯一の正**です。実装を変更したら必ずここを更新し、
`tests/` のテストが仕様の各項目を検証している状態を保ちます。

各項目の `[S-xxx]` は仕様IDです。テストコードのタイトルにこのIDを含めてください。

---

## 1. アプリ全体

### 1.1 画面構成 [S-APP-01]

| 領域 | 内容 |
| --- | --- |
| モードタブ | 🎵 音名クイズ / 🎯 度数クイズ / 🎹 コードシェイプ |
| 設定パネル | 現在のモードに関係する設定のみ表示する |
| 問題表示 | 見出し（`#question-label`）・問題（`#question-note`）・補足（`#question-sub`） |
| 指板 | SVG。0（開放弦）〜24フレット、**1弦が上・6弦が下**、**0フレットが左** |
| フィードバック | 正解／不正解のメッセージ |
| 操作 | 「選択をクリア」（コードモードのみ）／「次の問題 →」／「スコアをリセット」 |
| スコア | 正解数・出題数・正答率・連続正解・最高連続 |

- 音名クイズの設定は次の4行に分け、行間に控えめな1pxの横線を表示する。
  1. 音名表記・出題範囲・♯/♭表記・チューニング
  2. ブロック適用ON/OFF・方式・カスタム範囲またはスケール運指の選択・検証メッセージ／出典
  3. クリックで音を鳴らす・音色・音量
  4. 正解したら自動で次へ・音名表示（練習モード）
- 画面が狭い場合は各行の中で折り返し、行のまとまりは維持する。
  度数・コードモードでは1行目が各モードの出題条件とチューニングになり、ブロック行は非表示。
  サウンドと練習設定の行は共通とし、コントロールや設定値を複製しない。

### 1.2 モード切替 [S-APP-02]

- モードは `note` / `degree` / `chord` の3種。
- `#app` に `is-note` / `is-degree` / `is-chord` のいずれか1つが付く。
- 設定パネルの `.mode-note` / `.mode-degree` / `.mode-chord` は、対応するモードのときだけ表示する。
- モードを切り替えてもスコアは**モードごとに独立**して保持される。

### 1.3 設定の永続化 [S-APP-03]

- 設定は localStorage キー `guitar-game-settings` に保存する。
- 読み込み時は既定値とマージするため、キーが増えても既存ユーザーの設定は壊れない。
- 保存値が現在の選択肢に存在しない場合（旧バージョンの値など）は既定値に戻して保存し直す。

### 1.4 共通設定 [S-APP-04]

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| チューニング | スタンダード / ドロップD / 半音下げ | スタンダード |
| サウンド | ON / OFF | ON |
| 音色 | アコースティック / ガット / クリーン / クランチ / ディストーション / ブリッジミュート | アコースティック |
| 音量 | 0〜100% | 23% |
| 自動送り | ON / OFF | **ON** |
| 練習モード（全ポジション表示） | ON / OFF | OFF |

### 1.5 自動送り [S-APP-05]

- **既定は ON。**
- ON のとき、**正解した場合のみ**一定時間後に自動で次の問題へ進む。
  - 音名クイズ・度数クイズ: 900ms
  - コードシェイプクイズ: 1300ms（アルペジオ再生を聴ける時間を確保）
- **不正解のときは自動で進まない**（正解を確認させるため）。
- OFF のとき、および不正解のときは「次の問題 →」ボタンにフォーカスが移る。
- モード切替・設定変更時は予約済みの自動送りタイマーを破棄する。

### 1.6 サウンド [S-APP-06]

- 指板をクリックすると、その位置の実音高が鳴る（回答済みでも鳴る）。
- 音名／度数クイズで不正解のときは、550ms 後に正解位置の音を鳴らす。
- コードシェイプクイズで正解したときは、シェイプを低音弦からアルペジオ再生する。
  不正解のときは 500ms 後に正しいシェイプをアルペジオ再生する。
- 音色を変更したときは 3弦開放を試聴再生する。

### 1.7 キーボード [S-APP-07]

- `Enter` または `Space` で「次の問題 →」（ボタンが有効なときのみ）。

## 2. 音名クイズ [S-NOTE]

### 2.1 出題 [S-NOTE-01]

- ランダムな音名を1つ出題し、その音がある指板上の位置をクリックして答える。
- 同じ音名が2問続けて出題されない。

### 2.2 設定 [S-NOTE-02]

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| 音名表記 | `C D E F G A B` / `ド レ ミ ファ ソ ラ シ` | 英語 |
| 出題範囲 | ナチュラル音のみ（7音） / 全12音 | ナチュラル |
| ♯/♭の表記 | シャープ / フラット / 両方 | シャープ |
| ブロック適用 | ON（ブロック内の同じ音名をすべて探す） / OFF（指板全体で1か所選べば正解） | OFF |
| ブロック方式 | カスタム / スケール運指カタログ | カスタム |
| カスタムブロック | 開始弦〜終了弦（1〜6）、開始フレット〜終了フレット（0〜24、開放弦を含む） | 1〜3弦・0〜4フレット |
| スケール | メジャー／ナチュラルマイナー × 各12キー | Cメジャー |
| スケールのルート | 成立する弦・フレットから1位置 | 6弦8フレット |
| スケールの音域 | 高音側（ルート以上） / 低音側（ルート以下） / 両側（フォーム全体） | 高音側 |
| 運指パターン | 選択条件で成立するカタログの形 | 基本ボックス（6弦系） |

### 2.3 判定 [S-NOTE-03]

- 指板全体では、クリックした位置のピッチクラスが出題と一致すれば正解（オクターブ違いは問わない）。
- 正解: 押した位置に緑のマーカー、「正解！ 🎉」。
- 不正解: 押した位置に赤のマーカー、正解位置すべてに緑のマーカー、
  「残念… そこは 〇 です。〇 は緑の位置。」。

### 2.4 適用ON/OFF・カスタムブロックの指定と検証 [S-NOTE-04]

- 音名クイズの「ブロック適用」チェックボックスでON/OFFを切り替える。
  ONはブロック方式、OFFは従来の指板全体。切替時に進捗を消し、予約済み自動送りを取り消す。
  スコアと指定済み範囲は保持する。ON/OFFは既存の `noteScope`（`block` / `whole`）で保存・復元する。
- カスタムブロックは連続する弦と連続するフレットの長方形で指定し、両端を含む。
  例: 1〜3弦・0〜4フレット。ブロック設定は localStorage に保存・復元する。
- カスタム方式の「1オクターブ分の音名」は**全12種類のピッチクラスが少なくとも1つずつ存在すること**。
  単に最高音と最低音が離れているだけでは不十分。ナチュラル音の出題でも全12音を必要とする。
  現在のチューニングの実際の音で検証し、音名の出題範囲（7音／12音）は引き続き適用する。
- カスタム範囲の編集だけでは適用せず、OFFからONへの切替、またはON中の「範囲を更新」でまとめて反映する。
  ブロックの編集欄はOFFでも表示し、編集できる。「範囲を更新」ボタンはOFF中は無効。
  OFFへの切替は編集中の範囲が無効でも受け付け、最後に適用した有効な範囲を保持する。
  ONへの切替で検証に失敗した場合はチェックをOFFに戻す。
  不足・逆順・範囲外・整数以外は理由を表示し、適用済みの設定・問題・進捗は変更しない。
- カスタム方式に切り替えるときも検証する。使用中のカスタムブロックが全12音を含まなくなる
  チューニング変更は理由を表示して拒否する。
- 無効な保存済みブロックは既定の1〜3弦・0〜4フレットへ補正し、理由を画面と警告ログに示して保存する。
  無効な保存済み回答範囲は指板全体に戻す。

### 2.5 ブロック内の全位置回答 [S-NOTE-05]

- 出題された音名の**ブロック内の全位置**を選んで初めて正解。
  オクターブ違いだけでなく、同じ実音高の別ポジションもすべて対象とする。
- 正しい位置をクリックするたびに緑で表示し、「発見数／必要数」と残りの数を示す。
  同じ位置を再クリックしても二重計上しない（選択解除もしない）。
- 全位置がそろうまでは未回答であり、スコア・連続正解数を変えず、「次の問題」は無効。
  最後の正解位置を選ぶと1問だけ正解として加算し、自動送りONなら900ms後に次へ進む。
- ブロック内で違う音を選ぶと、その時点で1問だけ不正解として確定し、連続正解数を0にする。
  発見済み位置は緑のまま、誤答は赤、残りの正解位置は緑で表示する。自動送りしない。
  不正解後は従来どおり550ms後に近い正解位置の音を再生する。
- ブロック外のクリックは範囲内を選ぶ案内だけを表示し、進捗・スコア・判定を変えない。
  クリック音および回答後の試聴は従来どおり有効。
- 次の問題、リセット、回答範囲・ブロック・出題範囲・チューニングの適用時は選択を消す。
  ブロック音名モードへ戻ったときも新しい問題にする。スコアは従来の音名クイズと共有する。
- ブロック等の設定適用・モード切替では予約済み自動送りを破棄する。

### 2.6 カスタムブロックの指板表示 [S-NOTE-06]

- 適用中の弦・フレット範囲を問題の補足行に表示する。
- 指板は6弦×25ポジションのまま、ブロック全体を1つの外枠で囲み、外側を暗くする。
  内側のセルには枠線・常時の塗りを付けず、元の弦・フレット以外の縦横の補助線を描かない。
  外枠はクリックを遮らず、範囲変更時に更新し、指板全体や別モードでは取り除く。
- 練習モードの音名表示もブロック内だけを対象とする。
- 指板全体や度数・コードモードへ切り替えたら、ブロックの外枠・暗転・ラベル制限を外す。

### 2.7 スケール運指の全位置回答 [S-NOTE-07]

- スケール方式では、長方形内の全位置ではなく**カタログ運指に含まれる位置だけ**を回答対象にする。
  カスタム方式の全12音条件とは区別し、選んだスケールの7構成音と、
  指定ルートから上または下へ1オクターブ離れた同名音を含む運指だけを使用する。
  その1オクターブ内に7構成音がそろう必要があり、欠けた音を別オクターブだけで補っても有効にしない。
- メジャーは `0, 2, 4, 5, 7, 9, 11`、ナチュラルマイナーは `0, 2, 3, 5, 7, 8, 10` 半音。
  出題候補は運指にある音と「ナチュラル音／全12音」設定の共通部分。
  例えばC♯メジャーとナチュラル音設定ではC・Fから出題する。音名の異名同音表記は既存設定に従う。
- 同名音のすべての位置が必要。Rで表示した指定ルートも自分で選ぶ。
  途中経過、不正解、重複クリック、自動送り、スコアは [S-NOTE-05] と同じ。
- 外枠の内側でも運指にない位置は範囲外として扱い、不正解にはしない。
  スケール・運指を変更して現在の音が候補から消えた場合は、回答できる音へ更新する。
- 無効なルート・位置、位置の重複、7音や1オクターブ条件を満たさない位置集合は受け付けない。

### 2.8 出典付きスケールカタログ・音域展開 [S-NOTE-08]

- `src/core/scaleCatalog.ts` にメジャー7形・ナチュラルマイナー4形を収録する。
  各形は固有ID、元のキー、6弦→1弦のフレット配列、出典ID、採録・移調・部分抽出の説明を持つ。
  出典は公開教則の本文・図・TAB・教材データとし、単なる長方形から運指を生成しない。
- メジャー／ナチュラルマイナーを各12キーに移調できる。
  同じ弦にある目的のルートまで、原典の全フレットを同じ量だけ平行移動する。
  0〜24フレットからはみ出す候補は除外し、位置の補充や切り詰めはしない。
- 高音側は原典の指定ルート以上、低音側は以下の実音を抽出する。
  両側はルートより高い音と低い音を含む原典の全形。音域抽出はアプリの派生処理と明示する。
  どの場合も7構成音と完全な1オクターブを保つ。フレット番号の左右で音域を判定しない。
- 同じキー・ルート弦でも運指は複数あるため、一意の形とは扱わない。
  成立しない音域は選択肢に出さない。標準調弦のCメジャー6弦8fには、C2までの低音側1オクターブは存在しない。
- 使用する弦の標準調弦との差が一様な場合だけ利用する。半音下げは実キーを保って移調する。
  ドロップDでは6弦を含む候補を除外し、6弦を使わない運指部分だけを利用する。
- `docs/SCALE_CATALOG.md` は収録位置・位置数・実音域・根拠・制限を含み、
  `npm run catalog:scales` で同じデータから生成する。保存文書と生成結果の一致も検証する。

### 2.9 スケールの指板表示 [S-NOTE-09]

- 弦ごとの使用フレット範囲に沿った外周だけを表示する。隣接セル間の内枠線は描かない。
  元の弦・フレットは保持し、運指外の位置を暗くする。
- 回答対象に小さな○、指定ルート1か所に青いRを表示する。枠と○とRはクリックを遮らない。
  回答マーカーはその手前に重ね、発見済み・誤答の色を識別できる。
- 練習用の音名は運指の位置だけに表示し、Rには重ねない。
- 問題の補足にスケール・ルート弦とフレット・音域・パターン名・発見数を表示する。
  OFF・別モード・カスタム方式への切替ではスケールの○とRを除去する。

### 2.10 スケール選択UI・保存・切替 [S-NOTE-10]

- ブロック行で「カスタム」と「スケール運指カタログ」を切り替える。
  カスタムの弦・フレット欄と更新ボタン、スケールの選択欄は方式に応じて排他的に表示する。
- スケールではキーと種類、ルート弦、ルートフレット、音域、運指パターンの順で選ぶ。
  成立する候補だけを弦→フレット→音域→パターンの順で絞り込む。
  スケール名は音名表記・♯/♭表記に追従する。説明と選択中のパターンの出典リンクを表示する。
- スケール条件は変更時に即時反映し、別途「範囲を更新」は不要。
  条件変更で元の選択が使えなくなった場合は、同じルート弦→最も近いルートフレット→同じ音域→同じパターンの順で優先する。
  適用OFFのまま選択を変更でき、変更だけでONにはしない。
- `noteBlockSource` と `noteScale` に方式・選択条件を保存する。
  カスタム範囲とスケール条件は独立に保持し、切替で相互に上書きしない。
  古い保存設定ではカスタムを維持する。無効な保存値は有効な候補・既定値へ補正し、画面と警告ログで理由を示す。
  形式が有効でも現在の条件で成立しないスケール選択は、カスタム方式の使用中も補正・保存・通知する。
  再読み込み後は補正済みの選択を復元し、同じ理由の補正通知を繰り返さない。
- スケール適用中に選択ルート弦が成立しなくなるチューニング変更は拒否する。
  それ以外は有効な候補へ更新し、ルート位置や音域が変わる場合は通知する。
  OFF中は新しいチューニングで使える候補に更新する。
- 方式・条件・適用ON/OFFの変更では進捗をクリアし、自動送りをキャンセルする。音名クイズのスコアは保持する。
  モードを戻すと選択済みスケール運指を復元して新しい問題を出す。

## 3. 度数クイズ [S-DEG]

### 3.1 出題 [S-DEG-01]

- 指板上にルートを青い **R** で表示し、そこから見た度数（例: `III`、`m3`）を出題する。
- ユーザーは該当する度数の位置をクリックして答える。
- 同じ度数が2問続けて出題されない。

### 3.2 設定 [S-DEG-02]

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| 度数の表記 | ローマ数字（♭III） / 音程名（m3） | ローマ数字 |
| 出題する度数 | コードトーン / メジャースケール / ナチュラル・ハーモニック・メロディックマイナー / メジャー・マイナーペンタトニック / ブルース / 全12音程 | コードトーン |
| ルートの決め方 | 毎問ランダム / ルート音を固定 / ルート位置を固定 | ランダム |
| ルートの弦 | 1〜6弦から複数選択（最低1本） | 6弦・5弦 |
| 回答できる範囲 | ルート周辺（±4フレット） / 指板全体 | ルート周辺 |

- ルートは 0〜12フレットに配置する。

### 3.3 判定 [S-DEG-03]

- 押した位置のルートからの度数が出題と一致し、かつ回答範囲内なら正解。
- 度数は合っているが回答範囲外のときは、通常の不正解とは区別したメッセージを出す。
- 不正解時は正解位置に緑のマーカーと度数ラベルを表示する。

## 4. コードシェイプクイズ [S-CHORD]

### 4.1 出題 [S-CHORD-01]

- コードネーム（例: `Cmaj7`）を出題し、指板を**複数クリック**して押さえる。
- 同じ「コード種類 × ルート位置」が2問続けて出題されない。

### 4.2 ボイシング [S-CHORD-02]

| ID | 表示 | 押さえる音 | 音数 |
| --- | --- | --- | --- |
| `triad` | トライアド（R・3rd・5th） | R, 3rd, 5th | 3 |
| `seventh` | セブンス（R・3rd・5th・7th） | R, 3rd, 5th, 7th | 4 |
| `guide` | ガイドトーン（R・3rd・7th／5th省略） | R, 3rd, 7th | 3 |
| `form` | コードフォーム（開放・バレー） | 構成音＋オクターブ重複 | 4〜6 |

- **オクターブ重複の有無でボイシングを分ける。**
  - `triad` / `seventh` / `guide` は**オクターブ重複を含まない**。音数は表のとおり固定で、
    同じ音をオクターブ違いで重ねた押さえ方は正解にならない。
  - `form` は構成音を**オクターブで重ねた**開放コード・バレーコードの形（4〜6音）。
    E フォーム／A フォームのバレーコードや開放 C・G・D はここで出題する。
- 正解シェイプは理屈で網羅的に生成するのではなく、**定番コードフォームのカタログ
  （[S-CATALOG]）から導く**。実際に使われている押さえ方だけを正解とする。
- どの弦を使うか（隣り合う弦か、弦を飛ばすか）はカタログのタブ譜が決める。
  鳴らさない弦はミュートするものとして扱う。
- ボイシングはカタログエントリから次のように判定する（`catalogVoicing`）。
  1. 鳴っている音の数が**ピッチクラスの種類数より多い**（＝オクターブ重複がある）… `form`
  2. トライアド系のコード … `triad`
  3. セブンス系で省略音のないフォーム … `seventh`
  4. セブンス系で5度を省略したフォーム … `guide`（シェルボイシング）

### 4.3 コードの種類 [S-CHORD-03]

- 出題できるのは**カタログに定番フォームがあるコードだけ**（`catalogQualities(voicing)`）。
- `triad`: メジャー / マイナー / ディミニッシュ / オーギュメント / サスフォー
- `seventh`: maj7 / 7th / m7 / m7♭5 / dim7 / mMaj7
- `guide`: maj7 / 7th / m7 / mMaj7
  - m7♭5 と dim7 は**♭5がコードの identity**なので5度を省略できず、シェルボイシングが存在しない。
- `form`: メジャー / マイナー / ディミニッシュ / オーギュメント / サスフォー /
  maj7 / 7th / m7 / dim7 / mMaj7（m7♭5 は定番の開放・バレーフォームがない）
- 複数選択でき、**最低1つは選択されている**状態を保つ。

### 4.4 ルート弦 [S-CHORD-04]

- 6弦 / 5弦 / 4弦 / 3弦 / 2弦 / 1弦から複数選択（既定は6弦・5弦、最低1本）。
- 選べるのは、そのボイシング・そのチューニング・**選択中の転回形**で
  カタログに定番フォームがあるルート弦だけ（`catalogRootStrings(voicing, tuning, inversions)`）。
- **ルート弦は転回形に依存する。** 基本形はどの弦セットでも最低音弦がルートなので、
  高音弦ルートは転回形を選んだときだけ現れる（[S-CHORD-10]）。
- スタンダード／半音下げ（転回形をすべて選んだ場合）
  - `triad` / `seventh`: 6〜1弦すべて（基本形のみなら `triad` は6〜3弦、`seventh` は6〜4弦）
  - `guide`: **6弦・5弦のみ**（シェルボイシングは低音弦にルートを置く形だけが定番）
  - `form`: **6弦・5弦・4弦のみ**（開放・バレーコードは低音弦にルートを置く）
- ドロップD
  - 6弦だけ音程が違うため、6弦を使う定番フォームはそのままでは和音として成立しない。
    よって**6弦ルートは選べない**（`triad` / `seventh` は5〜1弦、`guide` は5弦、`form` は5弦・4弦）。
- `form` はコードの種類によって使えるルート弦が異なる（例: dim7 は5弦ルートのみ）。
  シェイプが作れないルート弦の小問は飛ばす（[S-CHORD-08]）。
- チューニングや転回形を変えたとき、選べなくなったルート弦は自動的に選択から外れる。

### 4.5 カタログからの正解シェイプ導出 [S-CHORD-05]

- ルート位置は 0〜12フレットからランダムに選ぶ（そのフレット範囲でシェイプを作れない場合は
  17フレットまで探索する）。
- 正解シェイプは `catalogChordShapes(tuning, voicing, quality, root)` が返す。手順は次のとおり。
  1. カタログから、**コード種類が一致し、ボイシングが一致する**エントリを集める。
  2. そのチューニングで和音として成立するエントリだけ残す（`isShapeValidIn`）。
     カタログのタブ譜はスタンダードチューニング前提の記譜なので、
     弦の音程差が違うチューニング（ドロップD）では成立しないフォームがある。
  3. 出題されたルート位置に合わせて**フレット方向に平行移動**する。
     - 移動可能フォーム（開放弦を含まない）だけが移調できる。
       開放弦を含むフォームは、記譜どおりの位置でルートが一致するときだけ使う。
     - 移調後のフレットが 1〜24 に収まらないものは除外する。
  4. 同じ押さえ方が複数のファミリーに登場することがあるので、**位置集合で重複を除く**。
- 候補は次の優先順で並べ、先頭を画面表示用の代表シェイプとする。
  1. ルートが低い順（基本形が先、展開形が後）
  2. フォームの系統順（オープン → CAGED → ドロップ2 → ドロップ3 → シェル → トライアド）
  3. 音数が多い順（定番のバレーコード形を優先）
  4. 弦の広がりが狭い順

### 4.6 回答 [S-CHORD-06]

- 「ルートを表示する」ON（既定）のとき、ルート位置に青い **R** を表示し、
  ユーザーは**残りの構成音だけ**をクリックする。
- OFF のときはルートも含めて全構成音をクリックする。
- クリックした位置はオレンジの「選択中」マーカーになる。
  もう一度クリックすると選択を解除できる。
- `form` は音数が可変なので、選択が**正解シェイプのいずれかと一致した時点で自動的に判定**する。
- 「最低音数」は、その小問の正解シェイプのうち**最も音数の少ないもの**に合わせる。
- 一致しないまま選び終えたときのために「**回答する**」ボタンを用意する。
  最低音数に達するまでは無効、判定後も無効。
- 選択できるのは最大で「6 − ルート表示分」音まで。
- 「選択をクリア」ボタンで、判定前の選択をすべて解除できる。
- 補足行には常に
  「ボイシング名 ／ ルート弦（何問目/全問） ／ ルート位置（表示ONまたは回答後のみ） ／ 選択状況」
  を表示する。選択状況は最低音数に届いていなければ「あと N 音以上（n 音選択中）」、
  届いていれば「n 音選択中」。`form` のときだけ「n 音選択中（オクターブを足してもOK）」と表示する。

### 4.7 判定 [S-CHORD-07]

- 選んだ位置の集合が**正解シェイプのいずれかと完全一致**したときに正解とする
  （展開形でも、弦を飛ばした形でも正解）。
- 正解: 選んだ位置を緑のマーカーにし、各音に度数ラベル（`R` `3` `5` `M7` など）を表示。
- 不正解: 間違えた位置を赤で表示し、**選択と最も重なりの多い正解シェイプ**を緑で表示する。

### 4.8 複数ルート弦の連続出題 [S-CHORD-08]

- 1つのコードに対して、**選択したルート弦の数だけ小問（ステップ）**を出題する。
  例: 6弦・5弦を選んでいれば `Cmaj7` を6弦ルート → 5弦ルートの順で2回答える。
- ステップは**低音弦から高音弦の順**に並ぶ。
- 転回形の連続出題が ON のときは、同じルート弦がその弦で作れる転回形の数だけ続く
  （[S-CHORD-10]）。
- シェイプが作れないルート弦は飛ばす。
- **途中で間違えても中断せず、すべてのステップを回答させる**。
- スコア（出題数・正解数）は**小問ごと**に加算する。
- 「次へ」ボタンのラベルは、残りステップがあるとき `次のシェイプ →`、
  最後のステップでは `次の問題 →` になる。
- 自動送りが ON のときは、**正解したときのみ**次のステップ／次の問題へ自動で進む（1300ms後）。
  不正解のときはボタン操作で進む。
- 出題時、選択したすべてのルート弦でシェイプを作れるコードを優先して選ぶ。
- 「次へ」の文言は、次の小問が同じルート弦なら `次の転回形へ`、
  別のルート弦なら `次のルート弦へ` になる。

### 4.9 押弦できるシェイプかの判定 [S-CHORD-09]

正解シェイプはカタログ（実際に使われている押さえ方）が正なので、この判定は
**カタログの品質チェックと指の本数表示**のために使う。次の2つを別々に扱う。

- **押弦幅**（押さえるフレットの最大値 − 最小値）
  - 最小フレットが 5未満（ローポジション）: **3フレット差以内**
  - 最小フレットが 5以上: **4フレット差以内**
  （`isSpanReachable`）
- **必要な指の本数**（`fingerCount`、親指は数えない）。本数は次のように数える。
  - 開放弦（0フレット）は指を使わない（0本）。
  - **最小フレット**に複数の音があるときは、人差し指のセーハで **1本**と数える。
    ただしセーハする弦の範囲の内側に、それより低いフレット（開放弦を含む）の音があるときはセーハできず、
    音の数だけ指が必要になる。
  - 最小フレット以外は、同じフレットでも 1音につき 1本と数える。
- `isPlayableShape` は「押弦幅が届く」かつ「指が4本以内（`MAX_FINGERS`）」のときに true を返す。
- カタログのフォームは原則としてこの条件を満たす。押弦幅の上限が保守的なため
  例外的に false になるエントリは、テストで既知の例外として固定してある。

---

### 4.10 転回形の選択 [S-CHORD-10]

**転回形（inversion）**は、コードのどの構成音を最低音に置くかで決まる。

| 番号 | 表示 | 最低音 |
| --- | --- | --- |
| 0 | 基本形 | ルート |
| 1 | 第1転回 | 3rd |
| 2 | 第2転回 | 5th |
| 3 | 第3転回 | 7th |

- 出題する転回形をチップで複数選択できる（最低1つ）。**既定は基本形のみ。**
- 選べるのは、そのボイシング・チューニング・**選択中のコードの種類**で
  カタログに定番フォームがある転回形だけ（`catalogInversions(voicing, tuning, qualityIds)`）。
  - `triad`: 基本形 / 第1転回 / 第2転回
  - `seventh`: 基本形 / 第1転回 / 第2転回 / 第3転回
  - `guide` / `form`: **基本形のみ**
    （シェルボイシングと開放・バレーコードは低音部にルートを置く形が定番で、
    転回形は定番フォームとして確立していない）
- **転回形を複数選んでいるときは、そのどれで答えても正解**になる。
  どれを狙うか指定されるのではなく、押さえられる形で答えればよい。
  - 出題時、補足行に `転回形 3種（基本形・第1転回・第2転回）のどれでも` と候補を示す。
    候補が1つのときはその名前だけを表示する（基本形だけを出題しているときは表示しない）。
  - 正解時、フィードバックに `第1転回でした` と**どの転回形だったか**を示す。
  - 連続出題が ON で転回形を複数選んでいるときだけ、
    まだ答えていないものを `残りは 基本形・第2転回` と続けて示し、
    出題エリアに**専用のバッジ（`#inversion-hint`）を出して目立たせる**。
    未回答なら `押さえるのは 基本形・第2転回 のどれでもOK`、
    回答後は `次に押さえるのは 第2転回`、
    その弦の転回形をすべて答えたら `🎉 この弦の転回形はすべて回答済み`（緑）。
    連続出題中は補足行から転回形の記述を外し、バッジに一本化する。
    OFF のときは続きの小問が無いので、残りの転回形は表示しない。
- 「**選んだ転回形を連続で出題する**」を ON / OFF で切り替えられる。
  - ON（既定）: 同じルート弦を、その弦で作れる転回形の数だけ繰り返し出題する。
    **判定した転回形は正解・不正解にかかわらず消費**し、
    その弦の転回形をすべて答え終えるまで次のルート弦へは移らない。
    逆に、答え終えていれば残りの小問は飛ばす。
    **2問目以降は、まだ答えていない転回形でなければ正解にならない。**
    順番は指定されないので、答えやすい形から埋めていける。
  - OFF: 1つのルート弦につき1問だけ。選んだ転回形のどれで答えてもよい。
  - 選べる転回形が1つしかないときは、この設定は無効（`disabled`）になる。
  - 答え済みの転回形は**ルート弦が変わるとリセット**される。
- 選んでいない転回形のシェイプは不正解。
- 転回形は最低音の度数で決まる。`positions` の中でルートが何番目かとは**一致しない**
  （3音の場合、ルートが2番目なら第2転回、3番目なら第1転回）。
- 補足行には、転回形を複数選んでいるか基本形以外を出題しているときだけ転回形名を表示する。

## 5. 定番コードフォームのカタログ [S-CATALOG]

`src/core/chordCatalog.ts` は、教則本やレッスンサイトで実際に教えられている
「定番の押さえ方」を集めたカタログである。
**コードシェイプクイズの正解判定はこのカタログが唯一の根拠**である（[S-CHORD-05]）。
理屈の上で成立する形をすべて列挙するのではなく、**実在する押さえ方だけ**を正解とする。

### 5.1 データ形式 [S-CATALOG-01]

1エントリ（`CatalogShape`）が1つの押さえ方を表す。

| フィールド | 内容 |
| --- | --- |
| `id` | 一意な識別子 |
| `qualityId` | `CHORD_QUALITIES` のコード種別 id |
| `root` | このタブ譜が表すコードのルート音（ピッチクラス） |
| `name` | 押さえ方の通称 |
| `family` | 系統（下記） |
| `tab` | `x-3-2-0-1-0` 形式。**6弦→1弦**の順、`x` はミュート |
| `sourceId` | `CATALOG_SOURCES` の出典 id |
| `omits` | 意図的に省略している構成音（ルートからの半音距離） |
| `note` | 補足 |

系統（`ShapeFamily`）は次の6種類で、すべて1件以上のエントリを持つ。

| 系統 | 内容 | 件数 |
| --- | --- | --- |
| `open` | 開放弦を含むローポジションの定番形 | 40 |
| `caged` | CAGED システムの移動可能フォーム（バレーを含む） | 28 |
| `drop2` | ジャズのドロップ2（隣り合う4弦） | 72 |
| `drop3` | ジャズのドロップ3（1本飛ばした4弦） | 48 |
| `shell` | 5度を省いたシェル／ガイドトーン | 16 |
| `triad` | 3声のトライアドボイシング | 60 |

**転記ミスを防ぐため、データとして持つのはタブ譜だけ**とする。
ルート弦・転回形・度数・移動可能かどうかは持たせず、すべて導出関数で計算する（[S-CATALOG-03]）。

出典は `CATALOG_SOURCES` に URL 付きで記録する。

### 5.2 構成音の正しさ [S-CATALOG-02]

すべてのエントリは、次を満たすことをテストで機械的に検証する。

- 鳴っている音のピッチクラス集合が、`CHORD_QUALITIES` の `intervals` と**過不足なく一致**する。
- ただし `omits` に宣言した音は欠けていてよい。宣言していない音の欠落・余分な音は不正とする。
- `omits` に宣言した音が実際に鳴っている場合も不正とする。
- **省略できるのは5度だけ**。ルート・3度・7度は省略しない。
- 宣言した `root` のピッチクラスが実際に鳴っている。

### 5.3 導出する情報 [S-CATALOG-03]

`analyzeCatalogShape(shape)` が次を計算する。
カタログのタブ譜は**スタンダードチューニング前提の記譜**なので、解析は常に
スタンダード（`CATALOG_TUNING`）で行い、チューニングを引数に取らない。

- `positions` — 低音弦から高音弦の順の `Position[]`
- `intervals` — `positions` と同じ並びの、ルートからの半音距離（0〜11）
- `rootString` — ルート音が鳴っている弦のうち、**最も低音側**のもの
- `inversion` — **最低音の度数**を基準にした転回番号（0 = 基本形）
- `movable` — 開放弦を含まず、任意のフレットへ移動できるか
- `noteCount` / `minFret` / `maxFret`

規約:

- 名前に「N弦ルート」と書かれているエントリは、`rootString` が N と一致する。
- 転回形の呼び方は**最低音基準**で統一する。
  出典によっては「元のクローズドボイシングの転回番号」で呼ぶことがあるが、それは採用しない。
  そのため `drop2` / `drop3` / `triad` の名前には転回番号を書かず、`型1`〜`型4` と呼ぶ。
- `open` 以外の系統はすべて `movable` である。


### 5.4 押弦できる形であること [S-CATALOG-04]

- 押弦するフレットの幅（最大 − 最小）が**4フレット差以内**に収まる。
- [S-CHORD-09] の `isPlayableShape()` は押弦幅の制限が保守的なため、
  実在するにもかかわらず通らないエントリが存在しうる。
  そのようなエントリは**既知のリストとしてテストに固定**し、意図しない増減を検出する。

### 5.5 タブ譜の変換・移動 [S-CATALOG-05]

- `parseTab(tab)` — 6弦→1弦のフレット配列に変換する。`x` は `null`。
  6弦ぶんでない、または負数・数値でない要素があれば例外を投げる。
- `tabToPositions(tab)` — 低音弦から高音弦の順の `Position[]` に変換する。
- `transposeTab(tab, semitones)` — 半音単位で移動する。
  開放弦を含むシェイプ、または移動先が負のフレットになる場合は例外を投げる。

### 5.6 カタログの検索 [S-CATALOG-06]

`findCatalogShapes({ qualityId, family, movable })` で絞り込む。
`CHORD_QUALITIES` の11種すべてに1件以上のエントリが存在する。

### 5.7 生成ドキュメント [S-CATALOG-07]

`docs/CHORD_CATALOG.md` は `npm run catalog` でカタログから自動生成する。手で編集しない。
コード・押さえ方の通称・タブ譜・ルート弦・転回形・構成音・備考を系統ごとの表にまとめ、
末尾に出典の URL を並べる。

生成物が古くなっていないことをテストで検証する。
カタログを変更したら `npm run catalog` を実行してから `npm run check` を通すこと。


### 5.8 別チューニングでの成立可否 [S-CATALOG-08]

タブ譜はスタンダード前提なので、弦の音程差が違うチューニングでは和音として成立しない
フォームがある。`isShapeValidIn(entry, tuning)`（`src/core/catalogShapes.ts`）が判定する。

- 平行移動しても弦ごとの音程差は変わらないので、**判定はタブ譜そのものの位置で1回行えばよい**。
- スタンダード・半音下げ（全弦が均等に −1半音）ではすべてのフォームが成立する。
- ドロップD（6弦だけ −2半音）では、**6弦を鳴らすフォームがすべて成立しない**。

## 6. テスト方針

- `npm run check`（= `tsc --noEmit` + `vitest run`）が通ることをもって「仕様を満たしている」とする。
- テストは `tests/` に置き、`describe` / `it` のタイトルに仕様ID（例: `[S-CHORD-05]`）を含める。
  - `tests/core.test.ts` — 音名・度数・チューニング・コードシェイプ生成の純ロジック
  - `tests/catalog.test.ts` — 定番コードフォームのカタログの機械検証（構成音・ルート弦・転回形）
  - `tests/quiz.test.ts` — `Quiz` / `DegreeQuiz` / `ChordQuiz` の出題・判定ロジック
  - `tests/app.test.ts` — jsdom 上で `src/main.ts` を実際に起動する結合テスト
    （画面構成・モード切替・設定の永続化・**自動送り**・キーボード操作）
